## Execution and state ownership

Native translation reuses the existing `Form::Table`, contiguous register-group
allocation and original opcodes. The two-register table has its original modulo-32
guest relation; the allocator packs it into existing caller-saved hardware
registers, including dirty/reused/aliased operands. There is no new vector bank,
software lookup in JIT, helper call, code instrumentation, runtime feature probe,
permission policy, fence, lock, service thread or JNI crossing. Host x18/TLS and
callee-saved state retain their original boundaries. LUT leaves NZCV/FPCR/FPSR
unchanged; surrounding integer/FP instructions retain their own real effects.

The shared reference gains only a compact decoded lookup operation over existing
vectors. Cached dispatch selects its original bounded-stack tail specialization;
the step path has the same architectural effects. This is reference/interpreter
execution, not an unavailable-host native fallback. No architectural extension
state is added. Original and current interpreter Op/Instruction/Entry/Cpu sizes
are **24/32/40/992 bytes**, unchanged. Native Operation/Block/Node/Frame remain
**192/152/264/120 bytes**.

- On actual **LUT-positive ARM64 Linux**, every one of the **589,824** legal words

  by assembly semantic fields rather than the production decoder. Full architectural
  state, exact one-instruction retirement and unchanged text are required, with
  zero fallback. Both cached and stepped interpreter paths each execute all
  589,824 words against the same independent oracle.

  overlaps and v31/v0 table wrap, all segments and varied NZCV/FPCR with sticky
  FPSR bits. Whole CPU state is checked, including unused vector/GPR/TLS banks.
- Dirty GPR/vector pressure, table repacking and original checked-memory callbacks
  run all forms across budgets 1/3/64 and serial/guarded/private modes. Precise
  faults after lookup preserve exact state/retirement. LDXR→LUT→STXR retains the
  original reservation domain. SVC resumption, explicit guest-authorized code
  replacement and execute-permission changes retain original cache authority.
- **576** cold compiled opcode/alias/pressure/mode programs retain actual LUT
  instructions and their width/segment fields, with no native helper calls.
- The full independent FP/AdvSIMD audit expands to **74,648 admitted selectors**
  under the declared v9.4+LUT feature mask, with zero invalid admissions or valid
  missing words. Old dated evidence remains frozen. Prior rejection tests exclude
  only newly allocated words found in the independent LUT selector fixture; the

## CPU-only lookup loops

The same current harness and binary execute JIT and reference interpreter modes,
with complete reference state/data, exact retirement and unchanged text checked
outside timing. Four balanced pairs alternate backend order on vCPU 0 of the same
LUT-positive ARM64 Linux VM. Each process has 16 samples with four warmups; each
sample has eight rounds of 65,536 trips through LUT + SUBS + B.NE, followed by
SVC. All **512** raw rows including warmups are retained; JIT rows require zero
fallback. Ratios are geometric means of four paired median interpreter/JIT times.

| CPU-only loop | Speed ratio over reference | Paired ratio range |
|---|---:|---:|
| luti2-byte | 57.778x | 57.373–58.963x |
| luti2-half | 32.498x | 32.352–32.602x |
| luti4-byte | 59.799x | 57.588–66.400x |
| luti4-half | 31.802x | 31.101–33.594x |

These are register-only steady-loop CPU measurements. They do not compare against
the old unsupported JIT, KVM backend, raw hardware loops, Android app-UID/ART,
graphics or application throughput; they do not establish universal multipliers.
Shared memory/network/graphics source-unchanged acceptance is reused. Generic
